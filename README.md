# shadowrocket-auto

自动收集公共节点，并在本地生成 Shadowrocket 订阅。

## 订阅发布状态

每小时工作流会把本轮生成的订阅**公开发布**到本仓库的 `gh-pages` 分支（`docs/shadowrocket.txt` 的内容强推至该分支），供 Shadowrocket 客户端直接订阅；质量报告（含哈希节点 ID、聚合统计与发现源地址，见下）提交回 `main` 分支。订阅里的节点全部来自公开渠道的免费分享节点，本项目不发布任何私有节点或自有凭据。

**注意**：`gh-pages` 上的订阅任何人可获取和解码（Base64 不是加密），其中节点 URI 含各分享节点的 UUID/密码——这些凭据本就由原分享者公开。不要把自己的私有节点 URI 加入采集源或提交到本仓库；如需托管私用订阅，请使用私有仓库或有访问控制的渠道。

## 安全说明

- 订阅源响应上限 2 MiB；每源最多 5,000 条、总计最多 20,000 条候选；单行最多 8 KiB。
- 配置订阅源最多 50 个、并发抓取 10 个；常驻发现源每轮另抓最多 40 个。普通源节点计入每轮 20,000 条的总量上限，优先源节点与发现到的散装节点不计入该上限（它们规模小且是精选/新发现信号）；每轮最多检测 5,000 个去重候选节点，优先源候选保送不占此名额，超出部分会在质量报告中计入 `skipped_limit`，避免大量恶意/重复节点拖垮定时任务。
- 单个订阅源下载总时限为 20 秒，覆盖首次请求、重试及重试等待（连接/读取超时也不会超过剩余总预算）；并发抓取按批次进行，达到总节点上限后停止后续批次。
- DNS 主机名会先做 IDNA 和标签格式校验；拒绝选项注入形式、空标签及非法字符，再调用 `getent` 做解析。
- 订阅源仅允许 HTTPS `raw.githubusercontent.com`，禁止自动跟随重定向，避免恶意源配置或跳转访问内网/本机服务。
- 域名解析通过 `getent ahosts` 子进程执行，硬超时为 2 秒；超时会终止解析进程并计入 timeout，不会无限占用采集线程。运行环境需要提供 `getent`（GitHub-hosted Ubuntu runner 默认具备）。
- VMess 主机和端口进行严格类型/范围校验；单个异常节点不会中断整批任务。
- DNS 答案只要包含非公网地址就拒绝；连接时使用已校验的解析结果。
- 每个节点有连接总时限，防止多地址轮询无限拖延。
- 公开工作流把不含节点 URI 的聚合质量报告提交回 main 分支，并把订阅文件发布到 gh-pages 分支（见「订阅发布状态」）；订阅文件在 main 分支上不被 Git 跟踪。
- 订阅文件和质量报告均先写入同目录临时文件，再通过原子替换落盘，避免中断时覆盖成半截文件；质量报告仅在订阅成功替换后标记 `updated`。
- 无可用节点时保留上一版订阅；报告会标注订阅是否更新。

**重要：Base64 不是加密。** 公开仓库中的订阅任何人都能解码，节点 URI 可能包含 UUID、密码和服务器地址。请只发布你有权公开的节点。私用订阅应使用私有仓库或受访问控制的发布渠道。如果历史提交曾含明文节点或真实凭据，仅删除当前文件不足以消除泄露，应轮换凭据并清理 Git 历史。

DNS 检查只在收集时发生；客户端稍后会重新解析域名，因此无法保证发布后 DNS 不变。不要简单把域名替换成 IP，否则可能破坏 TLS SNI、Host 或证书验证。

## 检测与排名

每小时任务先对 TCP 节点进行三次建连采样（至少两次成功），计算中位延迟和抖动；Hysteria2/Hy2、TUIC 等 UDP 节点不再冒充 TCP 可达。随后使用固定版本且 SHA-256 校验的 sing-box，在本机回环地址启动隔离的代理入口，通过真实代理隧道对候选节点下载 Cloudflare 测试数据（每节点最多两次、每次 256 KiB）。本项目为大陆客户端优化。测速分组按优先级：CF 前置 A/B（端点为 Cloudflare 地址段或 workers.dev / pages.dev）占 100、直连 A 档（VLESS Reality 与 443 端口 TLS）占 40、直连 B 档（其他 TLS）占 20、C 档（SS 等）占 40，某组不足时按优先级补位；组内按协议均衡，且每组名单按小时种子轮换切片，避免每小时重复测同一批节点。C 档在列是因为深圳实测表明：决定节点在大陆生死的不是协议，而是其服务/IP 段是否已被封锁编目——冷门 IP 段上的普通 SS 能连，而热门服务商的 Reality/CF 前置节点照样全灭（2026-11-20 实测）。因此订阅端设两道多样性闸门：按服务识别（协议＋凭据＋源站）每家最多留 2 个入口（同一节点换多个 CF IP 仍算一家），同一 /24 网段最多留 3 个节点（保送源节点放宽到 8 个——精选源里同网段整段可连的 SS 不应被限额误伤，2026-11-20 深圳实测后经确认放宽），逼订阅分散到几十家不同来源，靠分散存活。此外系统跨轮记录每个节点的存活历史（以哈希键随质量报告存回仓库）：首见满 24 小时、且至少 6 个轮次测活的「老兵」节点在测速名单中优先保位、订阅同档内排序靠前——实测中小而稳定的订阅（如 Pawdroid 仅 9 个节点却有 6 个可用）胜过每小时新选的节点，靠的正是这种长期存活信号，新面孔则继续通过轮换获得被验证的机会。此外 `config/priority_sources.txt` 可登记优先源（当前为 Pawdroid、v2rayfree、米贝订阅、End GFW 免费节点与 zmxoo 订阅）：这类小型精选订阅的节点每轮保送进候选与测速名单、不参加候选上限抽签，否则它们在上万候选的大池子里出勤率太低，存活资历永远攒不起来。源地址默认只允许 raw.githubusercontent.com；个别经逐个批准的非 GitHub 源（如米贝的 aa.mibei77.com、zmxoo 的 tian.zmxoo.xyz）记在代码的 EXTRA_SOURCE_HOSTS 白名单里，不开放通配。订阅格式除 URI 列表与 Base64 外也支持 Clash YAML：含 proxies 的文件自动逐条转成 URI 再走同一管线（SSR、Snell 与插件型 SS 跳过），go4sharing 的永久订阅（raw.githubusercontent.com/go4sharing/sub，频道从上千节点中预筛的幸存者名单）即以此接入（2026-11-22 批准）。小汐搬运（2026-11-22 批准，普通源）的节点嵌在博客 HTML 里，由专用解析器从其 Telegram 频道页定位最新帖子、剥标签提取 URI 后并入候选池。FreeClashNode（2026-11-22 批准，普通源）是每日源：其节点文件链接带日期、每天更换，采集器每轮先抓列表页解析当天文章、提取 node.freeclashnode.com 上的 V2ray 文本订阅（实测一天约 1,400 个有效候选），解析失败时按日期规律拼地址兜底；www 与 node 两个主机同在例外白名单里。此外系统带源发现（`scripts/discovery.py`，配置在 `config/discovery.json`）：每小时从 GitHub（代码/仓库搜索）、Telegram 公开频道、Google、YouTube 提取新出现的订阅地址与散装节点链接（X 渠道已预留，未配置公开账号前不启用）——发现层只访问这几个固定站点、不抓取搜索结果中的任意链接，发现到的订阅地址仍须通过同一套源白名单才会被抓取，散装节点则直接进入候选池走同一套筛选。有产出的发现源会保存在质量报告的 discovered_sources 里跨轮累积（连续 3 轮无产出或 7 天未见自动淘汰，上限 50 个），各渠道的产出与失败原因记录在报告的 discovery 段，渠道被封或失效不影响主流程。发布时节点统一改名为中文地区标记（旗帜＋中文地区＋协议＋序号，如「🇳🇿 新西兰 SS 01」），地区先由原名/主机名/SNI 关键词推测（覆盖 40+ 个国家地区，含「DE SS-34」式裸国家代码的词元识别，IN/IT/NO/AT 因与英文词冲突除外），直连节点仍推不出的再按端点 IP 查归属地兜底（ip-api，每轮上限 40 次、失败即跳过；CF 前置节点不查边缘 IP），都定不了的标「未知地区」；改名只动显示名，不影响端点、凭据与历史记录。测速为 4 路并行（同一出口带宽分摊会使 Mbps 数值略低于串行，只作粗排），总测速阶段设有 10 分钟硬预算。测速前重新校验 DNS 公网地址，并将 sing-box 连接目标固定到已验证 IP，避免 DNS 重绑定绕过地址过滤。只有完成完整下载的节点才进入订阅；发布另设「深圳实测白名单」（2026-11-21 晚实测：70 个订阅节点只有 14 个在深圳能连通）——只放行实测证明能活的 SS、Hysteria2、SOCKS5、VLESS Vision 直连与 VLESS GRPC 五类，WebSocket 传输不分协议一律排除，Trojan、VMess 等未证明能活的类型不进订阅；白名单只作用于发布选择，采集、测速与存活历史照常积累全部类型，实测口径变化时可随时放宽。另设「深圳实测认证网段」（config/field_verified_networks.txt）：用户在深圳逐个实测连通过的服务所在 /24 网段（2026-11-21/22 实测登记 9 段，如意大利 GTHost SS 段、西班牙住宅 Vision 段与七个 SOCKS5 段），段内节点在测速名单中与老兵同列优先、订阅排序中排在档位之前——两晚实测证明决定生死的是服务/IP 段是否被封锁编目，被实测证明未被编目的段值得最高优先；网段只来自真实实测，后续实测整批超时的段会移除。白名单之上再按实测做一层整形：VLESS Vision/GRPC 只保认证网段的（「住宅/移动出口」豁免保留五晚后取消：段外住宅 Vision 累计约 1/13），未达标者不论出口类型每轮仅留 3 个探索位；HY2 四晚存活约 3/42，订阅封顶 3 个探索位（认证网段不占名额）；未认证 SS 四晚约 1/23，同样只留 3 个探索位；SOCKS5 四晚约 12/13 存活且不挑网段，不设门槛、进测速名单优先。整形计数（vision_exploration_dropped / hy2_capped / ss_exploration_dropped）记入报告。订阅按 CF 前置优先、再按档位、同档内老兵优先、再按出口类型（住宅>移动>未测>机场>代理）、最后实测 Mbps 排序，且同一服务器（host:端口）只保留最快的一条；失败或不支持的节点不会伪造速度，也不会进入本轮新订阅。以上均为启发式规则，节点 IP 是否已被封锁无法从境外测得，大陆实际可用性不作保证。若没有节点通过测速，则保留上一版订阅。

当前转换器覆盖常见 VLESS（TLS/Reality、WS/gRPC/HTTP 传输）、Trojan、VMess、Shadowsocks（无插件）、Hysteria2、Hysteria v1、TUIC、AnyTLS、HTTP(S) 代理和 SOCKS5 分享链接（socks:// 与 socks5://，含 user:pass 整体 base64 的 userinfo 形式，SOCKS5 按裸协议归 C 档，AnyTLS 按 TLS 承载与 Trojan 同档）；SSR 与 Snell 因测速引擎 sing-box 不支持暂未覆盖（需另引入 mihomo 内核）；非标准传输、SS 插件及暂未支持的格式会明确跳过。GitHub runner 的测速结果受 runner 出口、测试服务和时段影响，不等于用户手机所在网络的实际速度。测速只使用受限大小的公共测试流量，不会对节点进行压力测试。质量报告公开哈希节点 ID、协议、测速 Mbps 和聚合统计，不公开节点服务器地址、UUID 或密码；例外是 discovered_sources 段以明文保存发现到的**订阅源地址**（公开订阅的 URL 本身，非节点凭据），用于跨轮累积常驻发现源。质量报告内的地区统计仍只按关键词推测；发布订阅的地区标记另有 IP 归属地兜底（见上），且归属地数据库对个别 IP 段可能有误，标记仅供参考。

## 本地运行

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/collector.py
```

本地生成 docs/shadowrocket.txt（Base64 订阅，按大陆可用性档位、再按实际 Mbps 排序）和 docs/quality_report.json（哈希 ID、测速统计与发现源状态）；订阅文件在 main 分支已加入 .gitignore，请勿手动提交（工作流发布走 gh-pages 分支）。UDP 候选（Hysteria/Hysteria2/TUIC）每轮取 40 个进入真实隧道测速，验证通过后与 TCP 节点一同入选订阅。

出口 IP 质量检测：节点测速通过后顺带经隧道实测其真实出口 IP，在内存中批量分类（数据中心/住宅/移动/已知代理出口＋出口国家），出口国家作为发布命名的最高优先级依据（优先于名字与服务器归属地推测），分类聚合与「标签地区≠出口国家」的错标计数写入质量报告；原始出口 IP 不落盘、不进报告。发布名末尾按出口类型加备注：住宅 IP 标「· 住宅」、数据中心（机场）IP 标「· 机场」，另有「· 移动」「· 代理」，测不到出口的节点不加备注。

## 配置

订阅源位于 config/sources.txt，每行一个 URL，支持 # 注释。请只添加可信来源。
